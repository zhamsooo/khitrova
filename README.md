# Сайт памяти Татьяны Ивановны Хитровой

Статический сайт (Cloudflare Pages) + Supabase (auth, БД, storage) — вики о жизни Т. И. Хитровой, её учениках и коллегах. Наполнение идёт через форму на сайте: любой залогиненный добавляет/правит, модератор проверяет и публикует.

## Стек

- Фронтенд — статика без сборки: `index.html`, `people.html`, `person.html`, `nasledie.html`, `moderation.html`, общий `app.js` и `style.css`. Деплой на Cloudflare Pages (`wrangler.toml`).
- Бэкенд — Supabase: Postgres (`supabase/*.sql` — схема и миграции, применяются вручную через SQL Editor), Auth (email OTP), Storage (аватары, изображения статей), письма модераторам/авторам через Resend (ключ — в Supabase Vault, не в репозитории).

## Структура

- `index.html`, `people.html`, `person.html`, `nasledie.html` — публичные страницы (таймлайн, каталог людей, карточка человека, статьи-наследие).
- `moderation.html` — очередь модерации (доступ по роли `is_moderator`/`is_admin`).
- `app.js`, `style.css` — общая логика и стили всех страниц.
- `supabase/` — SQL-схема и миграции (применяются вручную в Supabase Dashboard → SQL Editor, не автоматически).
- `data/kapellanin/` — вспомогательные данные, собранные с внешнего сайта kapellanin.ru (список учеников по классу дирижирования), для наполнения карточек людей.
- `docs/` — рабочие брифы и заметки по разработке (не предназначены для публикации как контент сайта).

## Локальная разработка

Сборки нет — статика открывается напрямую или через `wrangler pages dev`. Supabase-ключ на фронтенде — публичный `publishable`-ключ (`app.js`), его открытость в клиентском коде — норма; реальная защита данных обеспечивается политиками Row Level Security в `supabase/*.sql`.

## Известные незавершённые места

- `people.html`: на карточках каталога ещё остался старый абзац «Добавил(а)… Источник…» вместо унифицированной иконки метаданных (перенесено только на страницу человека).
- Контент (биография, фотографии) наполняется поэтапно — см. `docs/project-notes.md`.
