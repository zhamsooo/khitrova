# Задание v4: фронт — нейтральная палитра, шапка, таймлайн, «Люди», «Наследие»

Техзадание для ИИ-модели в репозитории. Прочитай целиком, затем `docs/design-rules.md` (правила M3; в этом задании их частично меняем — см. F0). Контекст и журнал — `docs/project-notes.md` (большой, читать только раздел «Журнал» за 2026-09-14). Бриф v3 (`docs/brief-redesign-v3.md`) выполнен: сайт на Material Design 3, Roboto, единый контейнер 1040. Здесь — правки владельца по итогам просмотра. Выполняй **только названную задачу** (F0–F6), не делай остальные «заодно».

## Что решил владелец (не обсуждается)
1. Палитра — **нейтральная**: белый фон, серые поверхности, чёрный как второй цвет. Фиолетовый убирается полностью.
2. Шапка — одна строка высотой 52px, как было до M3 (`git show v1-design:app.js`, `HEADER_HTML`): без имени Т.И., вкладки слева, справа «Добавить» → модерация → имя пользователя. FAB убирается совсем. Имя пользователя — полностью, и оно ведёт на его собственную карточку в «Людях».
3. Таймлайн на главной — **оригинальный вид TimelineJS**, без наших переопределений цветов и вёрстки. Единственное исключение — шрифт Roboto. Цель — устойчивость, не красота.
4. «Люди»: новый подзаголовок, поиск только по имени и году выпуска, фильтры по месту учёбы (Хоровое училище / Консерватория), «Коллеги», «Близкие» (вместо «Другое»), «Выдающиеся»; у каждого фильтра — число людей.
5. «Наследие»: сначала труды самой Т.И.; переключение табами, по умолчанию открыт таб Т.И.

## Метод: волнами
Каждая задача = одна сессия = один коммит. После каждой задачи сайт должен работать на всех пяти страницах (`index`, `people`, `person`, `nasledie`, `moderation`) — автодеплой публикует сразу. Если задача не влезает — закоммитить рабочее состояние, а не половину.

Правила поверх токенов:

- Filled-кнопка: `--primary`/`--on-primary`. Tonal: `--secondary-container`. Ссылки в тексте: `--on-surface`, подчёркнутые.
- Бейдж «На проверке»: `--tertiary-container` + иконка `schedule`. Подтверждённого бейджа на карточках нет (только у неподтверждённых).
- Проверить `grep -n "#6750A4\|#EADDFF\|#21005D\|#625B71\|#E8DEF8\|#7D5260\|#FFD8E4\|#FEF7FF\|#F7F2FA\|#F3EDF7\|#ECE6F0\|#E6E0E9" *.html *.css app.js` — должно быть пусто. Также найти `rgba(103,80,164` и подобные фиолетовые в inline-стилях страниц.

## F2. Шапка: одна строка 52px, «Добавить» в шапке, имя → своя карточка
Разметка `HEADER_HTML` в `app.js` и стили `.appbar/.tabs` в `style.css`:
1. **Одна полоса** `.appbar` высотой 52px, sticky, фон `--surface`, нижняя граница 1px `--outline-variant`. Внутри `.row` (контейнер 1040, gutter как везде). Отдельный `<nav class="tabs">` под шапкой удалить — вкладки переезжают в саму шапку.
2. **Слева** — вкладки «Линия жизни · Люди · Наследие» (`label-large`, зазор 24px, активная — `--on-surface` с индикатором 2px `--primary` по нижнему краю шапки; неактивная — `--on-surface-variant`). Заголовка «Татьяна Ивановна Хитрова» в шапке нет.
3. **Справа, слева направо:** кнопка «Добавить» (`.btn.tonal`, иконка `add`, высота 36px; гостю открывает вход, залогиненному — `openAddModal()`), иконка модерации с бейджем (только модератору, как сейчас), блок пользователя. Кнопку `navSearchBtn` из шапки удалить — поиск живёт на странице.
4. **Блок пользователя (залогинен):** аватар-инициал 32px + полное имя (`label-large`, `white-space:nowrap`, без обрезки на десктопе) + стрелка `expand_more`. Клик по имени/аватару → переход на свою карточку (`goToMyCard()`, п.6). Клик по стрелке → выпадающее меню: «Моя карточка», «Модерация» (модератору), «Выйти». Гость: text-кнопка «Войти».
5. **Телефон < 600px:** шапка та же 52px; вкладок в ней нет (остаётся нижний navigation bar как сейчас); справа — «Добавить» как `.iconbtn` с `add` и аватар (имя скрыто, тап по аватару открывает меню, первой строкой — полное имя). **FAB удалить полностью**: HTML в `HEADER_HTML`, обработчик `fabAdd`, CSS `.fab`, нижние отступы страниц под FAB (клиренс 96px) уменьшить до отступа под navigation bar.
6. **Своя карточка.** Миграция `supabase/migration_front_v4.sql` (см. F4, общий файл): `alter table public.profiles add column if not exists person_id uuid references public.people(id);`. Политика «profile: обновляет только владелец» уже есть. Функция `goToMyCard()` в `app.js`:
   - если `myProfile.person_id` есть → `person.html?id=…`;
   - иначе искать `people` по имени: `full_name` равно `profile.full_name` без учёта регистра и «ё/е», среди видимых пользователю строк; ровно одно совпадение → сохранить `person_id` в профиль (update своей строки) и перейти;
   - иначе → открыть единый диалог добавления на табе «Человек», поля предзаполнить из профиля (`full_name`, `relation_type`, `study_end`), под формой supporting text «Это будет ваша карточка на сайте»; после успешной вставки записать `person_id` = id новой строки и перейти на `person.html?id=…` (автор видит свою неподтверждённую карточку по RLS).
   - При входе (`onLoggedIn`), если `person_id` пуст, один раз тихо выполнить только поиск по имени (без диалога).
   - В `select` профиля при загрузке (`profiles`) добавить `person_id`.
Критерий: на 1280 шапка — одна строка 52px, левая линия вкладок совпадает с контентом; на 375 — шапка 52px без обрезок, FAB нигде нет, navigation bar работает; клик по имени открывает карточку (или диалог создания с предзаполненным именем).

1. **Подзаголовок** (`people.html`, `.lead`): «Ученики, коллеги и все, с кем была знакома Татьяна Ивановна. Список неполный — пожалуйста, дополняйте его.»
2. **Поиск**: placeholder «Имя или год выпуска». Искать только по `full_name` и по годам (`study_start`, `study_end`, `choir_school_*`, `conservatory_*`, `assistantship_*`). `institution`, `notes`, `relation_type` из строки поиска убрать. Иконку поиска в шапке (F2) не возвращать.
3. **Фильтры** — chips с числом людей в каждом (число — `label-medium`, `--on-surface-variant` на невыбранном, `--on-primary` на выбранном, формат «Консерватория · 12»). Счётчики считаются по загруженному списку (до применения поиска), пересчитывать не нужно. Chip с нулём не прятать, а показывать приглушённым (`opacity:.6`), кликабельным.
   - «Все» — всё.
   - «Хоровое училище» — `relation_type='ученик'` и `studied_choir_school`.
   - «Консерватория» — `relation_type='ученик'` и (`studied_conservatory` или `studied_assistantship`). Ассистентура-стажировка — послевузовская ступень консерватории, поэтому она здесь же; на карточке различается подписью.
   - «Коллеги» — `relation_type='коллега'`.

   - «Выдающиеся» — `notable = true` (новое поле, п.5). На карточке рядом с именем иконка `star` 16px, `--on-surface-variant`.
   - URL-параметр `?filter=` (используется хлебной крошкой `person.html`): значения `все | choir | conservatory | коллега | близкие | notable`; крошку синхронизировать.
   - Ученики без флагов учебного заведения (сейчас это все 39 записей из архивного списка) попадают только во «Все» и, если отмечены, в «Выдающиеся» — это ожидаемо, данные дополнит владелец.
4. **Подпись на карточке** (`sub`): роль · выпуск · заведение, полными словами: «Ученик · выпуск 1987 · Хоровое училище», «Ученица · СПбГК, ассистентура», «Коллега», «Близкий человек». Сокращения «Хор. уч.», «Ассист.» убрать. Если пол неизвестен, слово «Ученик(ца)» не писать: «Выпуск 1987 · СПбГК» (без роли), а если и года нет — «Ученик» без скобок.
5. **Миграция** `supabase/migration_front_v4.sql` (идемпотентная; **не применять самому**, в отчёте написать «готова к применению»):
   - `alter table public.people add column if not exists notable boolean not null default false;`
   - `alter table public.profiles add column if not exists person_id uuid references public.people(id);` (из F2)
   - `create or replace function public.apply_revision(...)` — скопировать целиком из `supabase/migration_revisions.sql` и добавить в ветку `person` строку `notable = case when rev.patch ? 'notable' then (rev.patch->>'notable')::boolean else notable end,`. Остальное тело функции — без изменений.

6. **Флаг в формах**: чекбокс «Выдающийся ученик (известный дирижёр, звания, лауреат)» в едином диалоге добавления (таб «Человек»), в форме «Предложить правку» на `person.html` (уходит в `patch.notable`) и в форме модератора на `moderation.html`.
